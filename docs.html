01 Runtime overview

One authority. Several presentations.

Claude of Tanks is a Vite application using Three.js directly—no Unity export, Unreal stream, React rendering layer, or game-engine runtime. The browser renderer is intentionally downstream from a renderer-free deterministic combat authority.

Current public truth: 80 selectable original first-party vehicles, eight generated battlefields, a 60 Hz authority, viewer-filtered multiplayer state, and no credits, XP economy, or tech-tree gate.

02 First-party fleet

The vehicle is a shared specification.

A vehicle spec supplies dimensions, mass, engine and gearing, gun limits, shells, armor plates, modules, crew, concealment, texture programs, and visual metadata. That identity is shared by the garage, icon generator, battle loader, authority, bot roster, armor model, and renderer.

Procedural geometry

Authored hull/turret stations, plate forms, fittings, and native running gear are assembled by tankFactory.js.

Gameplay geometry

Armor is explicit data with thickness, material, slope, coverage, composites, spaced layers, and ERA behavior.

Grounded presentation

Wheel and link paths follow real running-gear topology and terrain support instead of a rigid decorative strip.

Runtime provenance

Playable vehicles are original first-party builds. Community/reference GLBs are quarantined comparison material, not runtime replacements.

The procedural stand-in / streaming-GLB architecture is retired for playables. Public builds strip quarantined source material. Historical rebuild ledgers remain in the repository as provenance, not as a description of the deployed runtime.

04 Fixed-step authority

Render rate never changes the rules.

Movement and combat advance in fixed 1/60-second steps. Engine force, gearing, steering, braking, slope response, tank/prop collision, support points, spotting, shells, fire, repair, bots, and match pacing remain independent of the display frame rate.

  1. Inputs are normalized and ordered.
  2. The authority advances vehicle movement and terrain contact.
  3. Spotting updates viewer knowledge.
  4. Guns, shells, collision, armor, and damage advance.
  5. Bots choose their next valid controls.
  6. Durable state and one-shot events are published.

A clamped frame accumulator prevents a backgrounded tab or long frame from applying one giant physics integration. Bots use the same movement, visibility, gun, and damage paths as human players, with seeded varied openings and recovery/replanning rather than a single memorized route.

05 Aim and armor

The center point requests. The gun obeys physics.

The center-screen camera ray establishes the desired world aim point. Turret yaw and gun pitch track it one-to-one, subject only to the selected vehicle's traverse arc, rotation rate, elevation, depression, and physical obstruction. The separate gun marker displays where the bore can actually fire now.

Aim rayCenter of screen → desired world pointcamera
Turret solveDesired point → clamped yaw and gun pitchlimits
MuzzleResolved bore transform + dispersionweapon
ImpactPlate angle → ricochet / overmatch / penetration / damageauthority

AP, APCR, HEAT, HE, and APFSDS have distinct muzzle velocity, drop, falloff, ricochet/normalization behavior, and damage logic. The killcam and shot report display the already-resolved shell path, impact angle, effective armor, roll, damaged internals, and outcome; they do not recalculate the shot.

06 Network model

Clients send intent, never truth.

ModeAuthorityTransport
Solo vs botsLocal browserDirect composition
LANTrusted browser hostDirect Wi-Fi WebRTC
Private codeTrusted browser hostWebRTC + ICE/TURN fallback
RankedDedicated Node serviceAuthenticated WebSocket

Protocol v3 validates a finite envelope vocabulary with sequence, acknowledgement, and simulation ticks. A client may submit throttle, steer, brake, world aim yaw/pitch, shell selection, fire, and consumable action bits. Position, hit, damage, spotting, reload completion, and victory stay authority-owned.

Split delivery

  • Reliable ordered control: handshake, lobby/room state, inputs, combat/destruction events, ping, errors, and leave.
  • Replaceable state: unordered zero-retransmit 20 Hz snapshots with acknowledgements, deltas, and periodic keyframes.

Remote tanks use adaptive buffered interpolation and bounded extrapolation. The local vehicle predicts the exact shared movement code, then reconciles and replays unacknowledged inputs. Heavy cosmetic events enter a bounded presentation queue; critical state applies immediately.

07 Persistent rooms

A result ends the round, not the room.

WaitingTeam, vehicle, equipment, map, and ready state editableroom state
StartingRoster locks and all peers load the selected worldround + 1
PlayingExisting WebRTC channels carry the matchauthority
ResultReport shows live play-again readiness; room returns to waitingsame peers

ROOM_COMMAND and ROOM_STATE travel on reliable control and carry room round, last result, roster, selection, team, and ready state. After the verdict, readiness resets and only the simulation runtime is replaced. Closing the report returns to the garage while staying in-room; the room strip remains under Battle. Ready locks vehicle/equipment/team edits until unready. Explicit Leave is the disconnect action.

Invite links carry the validated six-character room code and auto-join after the normal boot gate. LAN chooses the direct Wi-Fi WebRTC path automatically; signaling exchanges membership and ICE metadata but never carries gameplay.

08 Device contract

Scale pixels and decoration, not combat.

The first garage frame avoids combat-only work. Maps, family texture bakes, shader programs, wreck treatments, clouds, and optional diagnostics warm in post-ready idle slices or beneath an opaque transition. Quality policy controls resolution, shadows, post, texture sizes, vegetation, particles, and background scheduling independently.

  • Solo does not instantiate multiplayer transports or diagnostics.
  • Network presentation mutates state once; the main loop owns the single visual sync.
  • Snapshots and entity arrays are reused to avoid 120 Hz allocation churn.
  • Destruction FX are frame-budgeted during bursts.
  • A render-target watchdog restores the previous target even after GPU readback failure.

Press F3 for render/network diagnostics. Add ?diag=1 for boot render health. Network impairment QA supports latency, jitter, loss, and input loss without changing authority code.

09 Scene Studio

Production photography is a game mode.

Scene Studio runs a complete battlefield with combat paused. It places actual first-party vehicles, conforms them through the movement support solve, applies camo/damage, poses guns within spec, fires the real effects language, freezes a deterministic FX clock, and captures through the full renderer.

node tools/marketing-shots/gen-modern-showcase.mjs
node tools/marketing-shots/shoot.mjs \
  --scenes tools/marketing-shots/scenes-modern \
  --out shots/marketing-modern/raw --width 1600
node tools/marketing-shots/encode-modern-showcase.mjs

The landing-page set contains 30 newly authored, modern-only scenes. Broad turret search arcs and vehicle-authored gun elevation/depression replace the repeated catalog pose; the generated manifest records each requested turret angle, gun angle, pose, map, nation, and vehicle. Scene JSON is checked in, raw PNG evidence is reproducible, and deployable WebP files are budget encoded. See the complete Studio API.
